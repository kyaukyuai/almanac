# v0.13 RC Smoke

This is the release-candidate smoke for the v0.13 Personal Almanac
Maintenance release. It validates the local maintenance loop for a personal
user: create an offline almanac, author answer fixtures, run provider-free
maintenance, inspect saved maintenance evidence, preview repair and cleanup,
and generate caller-owned scheduler handoff snippets.

Run from the repository root. Use fresh disposable roots. Sections 1-6 are
provider-free. Section 7 is provider-backed and requires `ANTHROPIC_API_KEY`.

## 3. sqlite-demo Creation And Answer Fixtures

Create a fresh offline demo and save one deterministic answer artifact:

```bash
SQLITE_ROOT="$(mktemp -d -t almanac-v013-sqlite-smoke)"

bun src/cli.ts demo --root "$SQLITE_ROOT"
bun src/cli.ts inspect sqlite-demo --root "$SQLITE_ROOT"
bun src/cli.ts profile sqlite-demo --root "$SQLITE_ROOT"
bun src/cli.ts benchmark sqlite-demo --root "$SQLITE_ROOT"

export ALMANAC_LLM=mock
export ALMANAC_MOCK_RESPONSES="$(
  cat <<'JSON'
{
  "answer-planner@planner-v1": [
    "{\"action\":\"call_tool\",\"toolName\":\"query_facts\",\"input\":{\"q\":\"transactions atomic\",\"limit\":3}}",
    "{\"action\":\"stop\",\"reason\":\"enough-evidence\"}"
  ],
  "answer-synthesis@synthesis-v1": "{\"status\":\"ok\",\"answer\":\"SQLite transactions are atomic.\",\"citations\":[{\"sourceId\":\"sqlite-transactions\",\"url\":\"https://www.sqlite.org/lang_transaction.html\",\"fetchedAt\":\"2026-01-01T00:00:00.000Z\"}]}"
}
JSON
)"

sqlite_answer_json="$SQLITE_ROOT/sqlite-answer.json"

bun src/cli.ts ask sqlite-demo \
  "Are SQLite transactions atomic?" \
  --save \
  --label rc-answer \
  --json \
  --root "$SQLITE_ROOT" \
  > "$sqlite_answer_json"

jq '{answerId, status, citations: (.citations | length), toolCalls: (.toolCalls | length), quality: .trace.quality.status}' \
  "$sqlite_answer_json"

sqlite_answer_id="$(jq -r '.answerId' "$sqlite_answer_json")"

unset ALMANAC_LLM
unset ALMANAC_MOCK_RESPONSES
```

Expected result:

## 4. Provider-Free Maintenance Apply

Fresh `sqlite-demo` intentionally has no source fetch manifest, so a normal
maintenance apply will recommend `04-source-fetch` and require provider-backed
stages. For the provider-free RC path, mark demo sources as freshly checked and
remove the benchmark report so maintenance is due only at the deterministic
benchmark boundary:

```bash
now="$(date -u +%Y-%m-%dT%H:%M:%S.000Z)"

jq --arg now "$now" '{
  schemaVersion: "0.1.0",
  almanacId: "sqlite-demo",
  startedAt: $now,
  finishedAt: $now,
  summary: {
    total: (.sources | length),
    fetched: 0,
    indexOnly: (.sources | length),
    failed: 0,
    totalDocuments: 0,
    totalBytes: 0
  },
  entries: [.sources[] | {
    sourceId: .id,
    status: "index-only",
    fetchedAt: $now,
    finalUrl: .url,
    fetcher: "rc-smoke",
    indexMeta: {label: "rc-smoke fresh marker"}
  }]
}' "$SQLITE_ROOT/sqlite-demo/sources/sources.json" \
  > "$SQLITE_ROOT/sqlite-demo/sources/manifest.summary.json"

rm "$SQLITE_ROOT/sqlite-demo/.compile/benchmark-result.json"
```

Run dry-run and apply maintenance:

```bash
bun src/cli.ts maintain sqlite-demo \
  --dry-run \
  --json \
  --root "$SQLITE_ROOT" \
  | tee "$SQLITE_ROOT/maintain-dry-run.json" \
  | jq '{status, dryRun, refresh: {due: .refresh.due, recommendedFromStage: .refresh.recommendedFromStage}, benchmark: .benchmark.status, answer: .answer.status, plan: [.plan[] | {id, status, providerRequired}]}'

bun src/cli.ts maintain sqlite-demo \
  --apply \
  --ask-suite \
  --label rc-maintenance \
  --json \
  --root "$SQLITE_ROOT" \
  | tee "$SQLITE_ROOT/maintain-apply.json" \
  | jq '{status, exitCode, refresh: .refresh.status, benchmark: .benchmark.status, askSuite: .askSuite.status, savedArtifact: .savedArtifact.relPath}'
```

Expected result:

- dry-run reports `recommendedFromStage: "12-benchmark-run"`,
- every planned step is provider-free,
- apply exits `0`,
- benchmark and ask-suite pass,
- a `.runs/maintain-*.json` maintenance artifact is saved.

Provider boundary check:

```bash
FRESH_ROOT="$(mktemp -d -t almanac-v013-provider-boundary-smoke)"
bun src/cli.ts demo --root "$FRESH_ROOT"

set +e
bun src/cli.ts maintain sqlite-demo \
  --apply \
  --json \
  --root "$FRESH_ROOT" \
  > "$FRESH_ROOT/provider-boundary.json"
boundary_exit=$?
set -e

jq '{status, exitCode, error, savedArtifact: .savedArtifact.relPath}' \
  "$FRESH_ROOT/provider-boundary.json"
test "$boundary_exit" -eq 1
```

Expected result:

- the command fails with `provider-required`,
- the failed maintenance attempt is still saved as evidence,
- this validates that provider-backed maintenance remains explicit.

## 7. Enterprise AI Provider Smoke

Run this section only when provider credentials are intentionally available.
The root is disposable; Enterprise AI remains generated on demand.

```bash
test -n "$ANTHROPIC_API_KEY" || {
  echo "ANTHROPIC_API_KEY is required for Enterprise AI RC smoke"
  exit 1
}

git switch main
git pull --ff-only

ENTERPRISE_ROOT="$(mktemp -d -t almanac-v013-enterprise-ai-smoke)"

bun src/cli.ts new "Enterprise AI" \
  --slug enterprise-ai-smoke \
  --profile mixed \
  --depth standard \
  --scope "Enterprise AI adoption and operations for organizations: AI governance, risk management, evaluation, security, compliance, deployment patterns, observability, and operating-model decisions for production AI systems." \
  --source "https://www.nist.gov/itl/ai-risk-management-framework" \
  --source "https://owasp.org/www-project-top-10-for-large-language-model-applications/" \
  --source "https://atlas.mitre.org/" \
  --root "$ENTERPRISE_ROOT"

bun src/cli.ts inspect enterprise-ai-smoke --root "$ENTERPRISE_ROOT"
bun src/cli.ts profile enterprise-ai-smoke --root "$ENTERPRISE_ROOT"
bun src/cli.ts benchmark enterprise-ai-smoke --root "$ENTERPRISE_ROOT"
bun src/cli.ts maintain enterprise-ai-smoke --dry-run --json --root "$ENTERPRISE_ROOT" \
  | jq '{status, refresh: .refresh.status, benchmark: .benchmark.status, answer: .answer.status, plan: [.plan[] | {id, status, providerRequired}]}'

bun src/cli.ts schedule print enterprise-ai-smoke \
  --target cron \
  --root "$ENTERPRISE_ROOT"
```

Run a real-provider answer and replay the saved artifact:

```bash
enterprise_answer_json="$ENTERPRISE_ROOT/enterprise-ai-smoke-answer.json"

ask_exit=0
bun src/cli.ts ask enterprise-ai-smoke \
  "What governance checks should precede production rollout?" \
  --save \
  --label rc-real-provider \
  --json \
  --root "$ENTERPRISE_ROOT" \
  > "$enterprise_answer_json" || ask_exit=$?

if [ "$ask_exit" -gt 1 ]; then
  cat "$enterprise_answer_json"
  exit "$ask_exit"
fi

answer_status="$(jq -r '.status' "$enterprise_answer_json")"
if [ "$answer_status" != "ok" ] && [ "$answer_status" != "abstained" ]; then
  cat "$enterprise_answer_json"
  exit 1
fi

jq '{answerId, status, citations: (.citations | length), toolCalls: (.toolCalls | length), quality: .trace.quality.status}' \
  "$enterprise_answer_json"

bun src/cli.ts ask-replay enterprise-ai-smoke \
  --from-runs \
  --label rc-real-provider \
  --json \
  --root "$ENTERPRISE_ROOT"
```

Expected result:

- compile/update pipeline reaches health `ok` or a clearly actionable
  attention state,
- benchmark passes and citation rate is nonzero,
- dry-run maintenance surfaces provider-required refresh steps explicitly,
- scheduler handoff renders without installing anything,
- real-provider answer exits `0` for `ok` or `1` for a valid abstention,
- saved answer replay passes without another provider call.
