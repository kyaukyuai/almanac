# v0.18 RC Smoke

This is the release-candidate smoke for the v0.18 Provider-Backed Studio
release. It validates provider readiness reporting, Studio reference intake
and goal staging, confirmation-gated compile and first answer through Studio,
the end-to-end first-use loop, no-key handoff parity, and the separated
Enterprise AI provider smoke.

Run from the repository root. Use fresh disposable roots. Sections 1-7 are
provider-free or use the deterministic mock provider only. Section 8 is
provider-backed and requires intentional credentials.

```bash
git switch main

git diff --check
bun run typecheck

```

Expected result:

- whitespace check passes,
- typecheck passes,
- full test suite passes, including the Studio end-to-end tests that spawn
  the real server with the mock provider.

## 6. End-To-End First-Use Loop In Studio

Continue on the same Studio server: promote the saved first answer to
replayable answer checks using only Studio operation POSTs.

```bash
find_operation() {
  curl -fsS "$studio_url/api/status/sqlite-demo" \
    | jq -r --arg prefix "$1" \
      '.operations[] | select(.command | startswith($prefix)) | .id' \
    | head -1
}
run_operation() {
  curl -fsS -X POST "$studio_url/api/operations/sqlite-demo/$1/run" \
    -H 'content-type: application/json' \
    -d '{"confirm":true}'
}

replay_id="$(find_operation "almanac ask-replay sqlite-demo --from-runs")"
test -n "$replay_id"
run_operation "$replay_id" | jq '{status, summary}'

promote_id="$(find_operation "almanac ask-fixtures add-from-run sqlite-demo answer-")"
test -n "$promote_id"
curl -fsS -X POST "$studio_url/api/operations/sqlite-demo/$promote_id/run" \
  -H 'content-type: application/json' \
  -d '{}' \
  | jq '{status, summary}'
run_operation "$promote_id" | jq '{status, artifactsWritten, summary}'
test -f "$DEMO_ROOT/sqlite-demo/tests/ask.jsonl"

suite_id="$(find_operation "almanac ask-suite sqlite-demo")"
test -n "$suite_id"
run_operation "$suite_id" | jq '{status, summary}'

evidence_id="$(find_operation "almanac refresh run sqlite-demo --from-stage 12-benchmark-run")"
test -n "$evidence_id"
run_operation "$evidence_id" | jq '{status, artifactsWritten, summary}'

curl -fsS "$studio_url/api/status/sqlite-demo" \
  | jq '{stage: .firstUse.stage, status: .firstUse.status, summary: .firstUse.summary}'

kill -INT "$studio_pid"
wait "$studio_pid" || true
```

Expected result:

- saved-answer replay runs through the Studio operation API,
- the promotion operation is rejected without explicit confirmation, then
  promotes the saved answer into `tests/ask.jsonl` behind `{"confirm": true}`,
- answer checks pass and refresh evidence saves through Studio,
- the final first-use stage is `replayable` or `maintainable` — the whole
  loop ran without leaving the browser surface.
