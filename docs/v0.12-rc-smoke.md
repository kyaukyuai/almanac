# v0.12 RC Smoke

This is the release-candidate smoke for the v0.12 Installed Almanac
Lifecycle release. It validates the local lifecycle that a personal user should
be able to run repeatedly: create or import an almanac, list it, inspect
status, ask and replay answers, refresh with ask validation, export/wiki it,
check registration state, and preview cleanup.

Run from the repository root. Use fresh disposable roots. Sections 1-6 are
provider-free. Sections 7-8 are provider-backed and require
`ANTHROPIC_API_KEY`.

## 1. Static Gates

```bash
git switch main
git pull --ff-only

git diff --check
bun run typecheck
bun test
```

Expected result:

- whitespace check passes,
- typecheck passes,
- full test suite passes.

```bash
SQLITE_ROOT="$(mktemp -d -t almanac-v012-sqlite-smoke)"
```

Run the existing detailed views and a deterministic tool call:

## 4. sqlite-demo Answer, Replay, Suite, And Refresh Visibility

Run a deterministic mock-provider answer and save the answer artifact:

```bash
export ALMANAC_LLM=mock
export ALMANAC_MOCK_RESPONSES="$(
  cat <<'JSON'
{
  "answer-planner@planner-v1": [
    "{\"action\":\"call_tool\",\"toolName\":\"query_facts\",\"input\":{\"q\":\"transactions atomic\",\"limit\":3}}",
    "{\"action\":\"stop\",\"reason\":\"enough-evidence\"}"
  ],
  "answer-synthesis@synthesis-v1": "{\"status\":\"ok\",\"answer\":\"SQLite transactions are atomic.\",\"citations\":[{\"sourceId\":\"sqlite-transactions\",\"url\":\"https://www.sqlite.org/lang_transaction.html\",\"fetchedAt\":\"2026-01-01T00:00:00.000Z\"}]}"
}
JSON
)"

sqlite_answer_json="$SQLITE_ROOT/sqlite-answer.json"

bun src/cli.ts ask sqlite-demo \
  "Are SQLite transactions atomic?" \
  --save \
  --label rc-answer \
  --json \
  --root "$SQLITE_ROOT" \
  > "$sqlite_answer_json"

jq '{answerId, status, citations: (.citations | length), toolCalls: (.toolCalls | length), quality: .trace.quality.status}' \
  "$sqlite_answer_json"

sqlite_answer_id="$(jq -r '.answerId' "$sqlite_answer_json")"

unset ALMANAC_LLM
unset ALMANAC_MOCK_RESPONSES
```

Replay the saved answer without a provider, create a fixture, and run the
provider-free suite:

```bash
bun src/cli.ts ask-replay sqlite-demo \
  --from-runs \
  --label rc-answer \
  --json \
  --root "$SQLITE_ROOT"

bun src/cli.ts ask-fixtures init sqlite-demo \
  --json \
  --root "$SQLITE_ROOT"

bun src/cli.ts ask-fixtures add-from-run sqlite-demo "$sqlite_answer_id" \
  --fixture-id sqlite-transactions-atomic \
  --json \
  --root "$SQLITE_ROOT"

bun src/cli.ts ask-suite sqlite-demo \
  --json \
  --root "$SQLITE_ROOT"
```

Persist refresh-integrated ask validation evidence and inspect saved artifacts:

```bash
bun src/cli.ts refresh due sqlite-demo \
  --json \
  --root "$SQLITE_ROOT" \
  | jq '{due, recommendedFromStage, reasons: [.reasons[].code]}'

bun src/cli.ts refresh run sqlite-demo \
  --from-stage 12-benchmark-run \
  --ask-suite \
  --save \
  --label rc-sqlite-ask-suite \
  --json \
  --root "$SQLITE_ROOT" \
  | jq '{status, refreshId, requestedFromStage, effectiveFromStage, askSuite: .askSuite.status}'

bun src/cli.ts runs sqlite-demo --latest --root "$SQLITE_ROOT"
bun src/cli.ts runs sqlite-demo --kind answer --root "$SQLITE_ROOT"
bun src/cli.ts runs sqlite-demo --kind refresh --root "$SQLITE_ROOT"

bun src/cli.ts status sqlite-demo --root "$SQLITE_ROOT"
bun src/cli.ts profile sqlite-demo --root "$SQLITE_ROOT"
bun src/cli.ts doctor sqlite-demo --root "$SQLITE_ROOT"
```

Expected result:

- saved answer status is `ok`, with at least one citation and one tool call,
- saved replay passes without provider credentials,
- `ask-suite` passes without provider credentials,
- saved refresh artifact records `askSuite.status=passed`,
- `runs` shows latest answer and refresh artifacts,
- `status`, `profile`, and `doctor` report answer readiness as ready.

## 5. Export, Import, Wiki, Registration, And Remove

Export a portable archive and validate the dry-run import path:

```bash
sqlite_archive="$SQLITE_ROOT/sqlite-demo.tar.gz"

bun src/cli.ts export sqlite-demo \
  --output "$sqlite_archive" \
  --root "$SQLITE_ROOT"

tar -tzf "$sqlite_archive" | head

IMPORT_ROOT="$(mktemp -d -t almanac-v012-import-smoke)"

bun src/cli.ts import "$sqlite_archive" \
  --root "$IMPORT_ROOT"

test ! -d "$IMPORT_ROOT/sqlite-demo"

bun src/cli.ts import "$sqlite_archive" \
  --apply \
  --root "$IMPORT_ROOT"

bun src/cli.ts status sqlite-demo --root "$IMPORT_ROOT"
bun src/cli.ts benchmark sqlite-demo --root "$IMPORT_ROOT"

bun src/cli.ts import "$sqlite_archive" \
  --as sqlite-copy \
  --apply \
  --json \
  --root "$IMPORT_ROOT" \
  | jq '{mode, targetId, manifestId: .manifest.almanacId}'
```

Generate the human-readable wiki and verify the file manifest:

```bash
WIKI_ROOT="$(mktemp -d -t almanac-v012-wiki-smoke)"
wiki_dir="$WIKI_ROOT/sqlite-demo-wiki"

bun src/cli.ts wiki sqlite-demo \
  --output "$wiki_dir" \

jq -r '.files[].name' "$wiki_dir/artifacts.json" | sort
```

Preview retention and removal cleanup without deleting data:

```bash
bun src/cli.ts runs sqlite-demo \
  --kind answer \
  --prune \
  --keep-latest 20 \
  --dry-run \
  --root "$SQLITE_ROOT"

bun src/cli.ts runs sqlite-demo \
  --kind refresh \
  --prune \
  --keep-latest 30 \
  --dry-run \
```

Expected result:

- default export excludes `.compile/` and `.runs/`,
- dry-run import validates the archive without writing `sqlite-demo`,
- applied import installs a runnable almanac into a second root,

  `benchmark.md`, and `artifacts.json`,

## 8. Enterprise AI Real Provider Ask, Saved Replay, And Suite

Run after the Enterprise AI compile smoke has produced `ALMANAC_ROOT`.

```bash
test -n "$ANTHROPIC_API_KEY" || {
  echo "ANTHROPIC_API_KEY is required for real provider ask smoke"
  exit 1
}

enterprise_answer_json="$ALMANAC_ROOT/enterprise-ai-smoke-answer.json"

ask_exit=0
bun src/cli.ts ask enterprise-ai-smoke \
  "What governance checks should precede production rollout?" \
  --save \
  --label rc-real-provider \
  --json \
  --root "$ALMANAC_ROOT" \
  > "$enterprise_answer_json" || ask_exit=$?

if [ "$ask_exit" -gt 1 ]; then
  cat "$enterprise_answer_json"
  exit "$ask_exit"
fi

answer_status="$(jq -r '.status' "$enterprise_answer_json")"
if [ "$answer_status" != "ok" ] && [ "$answer_status" != "abstained" ]; then
  cat "$enterprise_answer_json"
  exit 1
fi

jq '{answerId, status, citations: (.citations | length), toolCalls: (.toolCalls | length), quality: .trace.quality.status}' \
  "$enterprise_answer_json"

enterprise_answer_id="$(jq -r '.answerId' "$enterprise_answer_json")"

bun src/cli.ts ask-replay enterprise-ai-smoke \
  --from-runs \
  --label rc-real-provider \
  --json \
  --root "$ALMANAC_ROOT"
```

Promote the answer to an Enterprise AI fixture only when the saved answer is a
cited `ok` answer with at least one tool call. Correct abstentions are validated
by saved-run replay, but should not be promoted to provider-free fixtures because
fixture replay infers status from deterministic tool evidence.

```bash
if jq -e '.status == "ok" and (.citations | length) > 0 and (.toolCalls | length) > 0' "$enterprise_answer_json" >/dev/null; then
  bun src/cli.ts ask-fixtures init enterprise-ai-smoke \
    --json \
    --root "$ALMANAC_ROOT"

  bun src/cli.ts ask-fixtures add-from-run enterprise-ai-smoke "$enterprise_answer_id" \
    --fixture-id enterprise-ai-governance-rollout \
    --json \
    --root "$ALMANAC_ROOT"

  bun src/cli.ts ask-suite enterprise-ai-smoke \
    --json \
    --root "$ALMANAC_ROOT"

  bun src/cli.ts refresh run enterprise-ai-smoke \
    --from-stage 12-benchmark-run \
    --ask-suite \
    --save \
    --label rc-enterprise-ai-ask-suite \
    --json \
    --root "$ALMANAC_ROOT"
else
  echo "saved answer was not a cited ok answer; fixture promotion skipped"
fi

bun src/cli.ts status enterprise-ai-smoke --root "$ALMANAC_ROOT"
bun src/cli.ts profile enterprise-ai-smoke --root "$ALMANAC_ROOT"
bun src/cli.ts doctor enterprise-ai-smoke --root "$ALMANAC_ROOT"
```

Expected real-provider result:

- answer status is either `ok` with citations or a correct abstention,
- saved answer replay passes without another provider call,
- if a cited `ok` answer is promoted, default `ask-suite` passes without
  provider calls and saved refresh artifact records `askSuite.status=passed`,
- if the answer abstains correctly, fixture promotion is skipped,
- latest answer status, latest suite status, quality gate, retrieval mode, and
  lifecycle next actions appear in `status`, `profile`, and `doctor`.
