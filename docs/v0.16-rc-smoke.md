# v0.16 RC Smoke

This is the release-candidate smoke for the v0.16 Actionable Studio / Guided
Operations release. It validates the provider-free guided operation model, CLI
operation runner, Studio action API/UI, answer-readiness evidence save,
maintenance dry-run handoff, and the separated Enterprise AI provider smoke.

Run from the repository root. Use fresh disposable roots. Sections 1-5 are
provider-free. Section 6 is provider-backed and requires intentional
credentials.

## 1. Static Gates

```bash
git switch main
git pull --ff-only

git diff --check
bun run typecheck
bun test
```

Expected result:

- whitespace check passes,
- typecheck passes,
- full test suite passes.

Expected result:

- almanac-writing operations are not Studio runnable,

## 4. Studio Action API And UI

Start the local Studio on a random localhost port and inspect the action
surface. Use `--json` so the URL is machine-readable.

```bash
STUDIO_ROOT="$(mktemp -d -t almanac-v016-studio-action-smoke)"
bun src/cli.ts demo --root "$STUDIO_ROOT"
ANTHROPIC_API_KEY= BRAVE_SEARCH_API_KEY= bun src/cli.ts ask-fixtures init sqlite-demo \
  --seed-demo \
  --root "$STUDIO_ROOT"

studio_out="$(mktemp -t almanac-v016-studio-out)"
bun src/cli.ts studio \
  --port 0 \
  --json \
  --root "$STUDIO_ROOT" \
  > "$studio_out" 2>&1 &
studio_pid=$!

for i in $(seq 1 40); do
  if jq -e '.url' "$studio_out" >/dev/null 2>&1; then
    break
  fi
  sleep 0.25
done

studio_url="$(jq -r '.url' "$studio_out")"
test -n "$studio_url"

curl -fsS "$studio_url/" > "$STUDIO_ROOT/studio.html"
curl -fsS "$studio_url/api/inventory" > "$STUDIO_ROOT/studio-inventory.json"
curl -fsS "$studio_url/api/status/sqlite-demo" > "$STUDIO_ROOT/studio-sqlite-demo.json"

grep -E 'Guided Operations|Run|Fallback command|data-run-operation|sqlite-demo' \
  "$STUDIO_ROOT/studio.html"

jq '{count: .counts.total, actions: [.almanacs[0].operations[] | {id, label, providerRequired, mutation, studioRunnable, blockedReason}]}' \
  "$STUDIO_ROOT/studio-inventory.json"

jq '{activation, actions: [.operations[] | {id, label, providerRequired, mutation, studioRunnable, blockedReason}]}' \
  "$STUDIO_ROOT/studio-sqlite-demo.json"
```

Expected result:

- Studio binds to `127.0.0.1`,
- HTML includes Guided Operations, Run buttons for safe operations, and
  fallback command handling,
- `/api/inventory` and `/api/status/sqlite-demo` expose the same operation
  metadata as CLI status,
- provider-backed operations have `studioRunnable: false` and a blocked
  reason.

Run provider-free operations through the Studio POST API:

```bash
studio_ask_suite_id="$(
  jq -r '.operations[] | select(.category=="validate" and .studioRunnable==true and .providerRequired==false) | .id' \
    "$STUDIO_ROOT/studio-sqlite-demo.json" \
    | head -1
)"

studio_refresh_id="$(
  jq -r '.operations[] | select(.category=="refresh" and .studioRunnable==true and .providerRequired==false) | .id' \
    "$STUDIO_ROOT/studio-sqlite-demo.json" \
    | head -1
)"

studio_provider_id="$(
  jq -r '.operations[] | select(.providerRequired==true and .studioRunnable==false) | .id' \
    "$STUDIO_ROOT/studio-sqlite-demo.json" \
    | head -1
)"

test -n "$studio_ask_suite_id"
test -n "$studio_refresh_id"
test -n "$studio_provider_id"

curl -fsS -X POST "$studio_url/api/operations/sqlite-demo/$studio_ask_suite_id/run" \
  | tee "$STUDIO_ROOT/studio-operation-ask-suite.json" \
  | jq '{operationId, status, exitCode, provider, artifactsWritten, summary, next: .nextOperation.label}'

curl -fsS -X POST "$studio_url/api/operations/sqlite-demo/$studio_refresh_id/run" \
  | tee "$STUDIO_ROOT/studio-operation-refresh.json" \
  | jq '{operationId, status, exitCode, provider, artifactsWritten, summary, next: .nextOperation.label}'

curl -sS -X POST "$studio_url/api/operations/sqlite-demo/$studio_provider_id/run" \
  -o "$STUDIO_ROOT/studio-operation-provider-blocked.json" \
  -w '%{http_code}\n' \
  | grep '^200$'

jq '{operationId, status, exitCode, provider, summary, reasons}' \
  "$STUDIO_ROOT/studio-operation-provider-blocked.json"

curl -sS -X POST "$studio_url/api/inventory" -o /dev/null -w '%{http_code}\n' \
  | grep '^405$'

kill -INT "$studio_pid"
wait "$studio_pid" || true
```

Expected result:

- Studio POST returns the same operation result envelope as the CLI runner,
- safe read-only ask-suite execution returns `status: ok`,
- safe artifact-writing refresh evidence returns a `.runs/refresh-*.json`
  artifact and requires no provider,
- provider-backed actions return a blocked operation result rather than
  executing,
- unrelated POST requests remain rejected with `405`,
- page load and API reads do not call a provider.

Manual UI check, optional but recommended for RC signoff:

1. Open `$studio_url` before stopping the server.
2. Confirm safe operations show `Run` and provider-backed operations show only
   a copyable CLI handoff.
3. Click `Run` for `Run answer checks`.
4. Confirm the inline result panel shows status, summary, artifacts or "No
   artifacts written", next operation, and fallback command.

## 6. Enterprise AI Provider Smoke

Run this section only when provider credentials are intentionally available.
The root is disposable; Enterprise AI remains generated on demand.

```bash
test -n "$ANTHROPIC_API_KEY" || {
  echo "ANTHROPIC_API_KEY is required for Enterprise AI RC smoke"
  exit 1
}

git switch main
git pull --ff-only

ENTERPRISE_ROOT="$(mktemp -d -t almanac-v016-enterprise-ai-smoke)"

bun src/cli.ts new "Enterprise AI" \
  --slug enterprise-ai-smoke \
  --profile mixed \
  --depth standard \
  --scope "Enterprise AI adoption and operations for organizations: AI governance, risk management, evaluation, security, compliance, deployment patterns, observability, and operating-model decisions for production AI systems." \
  --source "https://www.nist.gov/itl/ai-risk-management-framework" \
  --source "https://owasp.org/www-project-top-10-for-large-language-model-applications/" \
  --source "https://atlas.mitre.org/" \
  --root "$ENTERPRISE_ROOT"

bun src/cli.ts inspect enterprise-ai-smoke --root "$ENTERPRISE_ROOT"
bun src/cli.ts profile enterprise-ai-smoke --root "$ENTERPRISE_ROOT"
bun src/cli.ts benchmark enterprise-ai-smoke --root "$ENTERPRISE_ROOT"
bun src/cli.ts operations enterprise-ai-smoke --json --root "$ENTERPRISE_ROOT" \
  | jq '{recommended: .recommendedOperation, operations: [.operations[] | {label, providerRequired, mutation, studioRunnable, blockedReason}]}'
```

Run a real-provider answer smoke and replay the saved run:

```bash
enterprise_answer_json="$ENTERPRISE_ROOT/enterprise-ai-smoke-answer.json"

ask_exit=0
bun src/cli.ts ask enterprise-ai-smoke \
  "What governance checks should precede production rollout?" \
  --save \
  --label rc-real-provider \
  --json \
  --root "$ENTERPRISE_ROOT" \
  > "$enterprise_answer_json" || ask_exit=$?

if [ "$ask_exit" -gt 1 ]; then
  cat "$enterprise_answer_json"
  exit "$ask_exit"
fi

answer_status="$(jq -r '.status' "$enterprise_answer_json")"
if [ "$answer_status" != "ok" ] && [ "$answer_status" != "abstained" ]; then
  cat "$enterprise_answer_json"
  exit 1
fi

jq '{answerId, status, citations: (.citations | length), toolCalls: (.toolCalls | length), quality: .trace.quality.status}' \
  "$enterprise_answer_json"

bun src/cli.ts ask-replay enterprise-ai-smoke \
  --from-runs \
  --label rc-real-provider \
  --json \
  --root "$ENTERPRISE_ROOT" \
  | jq '{mode, total, passed, failed, errored, quality: .quality.status}'
```

Expected result:

- compile pipeline completes with health `ok` or an explicitly diagnosed
  provider/network failure,
- benchmark passes and meets generated fixture minimums,
- guided operations show provider-backed work as CLI handoff and
  provider-free bounded work as runnable,
- real-provider answer exits `0` for cited `ok` or `1` for valid abstention,
- saved-run replay passes without a provider call.
